1 · Baseline form

Plain <form> with username + password. The icon should appear inside the right edge of both fields, vertically centred.

1b · Password field with a reveal (eye) button

The site puts its own show/hide toggle at the field's right edge — exactly where the XoraPass icon wants to sit. The icon must shift left of the eye rather than overlapping it. Toggle the eye and confirm both stay clickable and don't stack.

2 · No wrapping form

Inputs are siblings with no <form>. Exercises the document-wide fallback in findUsernameField.

3 · Decoy fields

A search box and a promo code sit before the password. The negative-hint rule should skip both and pick Account email — if the icon lands on search or promo, the heuristic regressed.

4 · Inside a scroll container

Scroll within the dashed box. The icon must track the field and disappear once the input leaves the box. This is where fixed-position overlays usually fail.

5 · React-style controlled input

Reproduces React's _valueTracker. A plain el.value = x hits the instance setter, so the tracker updates and the change is swallowed — the old bug. The fix calls the prototype setter, bypassing the tracker, so the change is seen.

6 · Injected after load (SPA)

Click to inject a login form. The MutationObserver should decorate it within a frame or two — the old 2.5s poll lagged noticeably here.

7 · Inside a modal

Opens a fixed-position overlay at z-index 100. The XoraPass icon must render above it (the overlay layer sits at max z-index).

7b · Sign-up form (password generation)

Two password fields with autocomplete="new-password". The icon should appear even with an empty vault, and the menu should lead with a suggested password. Using it must fill both boxes — leaving the confirm field empty would mean retyping 20 random characters by hand.

7c · Change-password form (must NOT capture)

Current password plus a new one. Because the filled values differ, capture should stay silent — which of the two to store is ambiguous. Submitting here should raise no save prompt.

8 · Cross-origin iframe

Framed from 127.0.0.1 while the page is localhost — a different origin. Autofill must be blocked inside it. Check the iframe's console for Autofill disabled inside third-party iframe. An icon appearing here is a security regression.

9 · Same-origin iframe

Same origin as the parent, so autofill should work here — confirms the frame check isn't over-blocking.
